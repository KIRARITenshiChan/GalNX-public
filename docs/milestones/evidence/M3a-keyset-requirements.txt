# M3-a 证据 E1: hacBrewPack keyset 需求实验（回答「是否需要 prod.keys」）
# 采集时间: 2026-10-30（脚本实测）+ 更早手工实验
# 采集人: audit-package (task-19)
# 安全: 全部实验只使用合成假值或只传真实 keyset 路径；本文件不含任何 key 内容。

## 1. 结论（先给答案）
- 需要 keyset：hacBrewPack 不能在没有 keyset 的情况下产出 NSP。
- 最小可用 keyset = header_key（32 字节 = 64 hex）+ key_area_key_application（16 字节 = 32 hex）；
  默认 keygeneration=1 时只要求 key_area_key_application_00 存在。
- 合成（假）keyset 能产出结构合法的 NSP，但 NCA 内容用假 key 加密，真机无法解密 → NOT INSTALLABLE。
- 真机可安装必须使用与目标机同代的真实 prod.keys（来源与合规性由使用方负责；本仓库不保存、不传输）。

## 5. 源码依据（hacBrewPack v3.05 / 745b16ec，main.c）
- main.c:100         settings.keygeneration = 1;（默认 keygeneration=1）
- main.c:320-344     若 key_area_key_application[keygeneration-1][0] 全 0 →
                     "Error: key_area_key_application for keygeneration %i is not present in keyset file"
                     若 header_key 全 0 → "Error: header_key is not present in keyset file"
- main.c:410-414     打印 "Key area key %i: <hex>"（--keyareakey 的独立设置，默认 0x04×16，
                     不是从 prod.keys 派生）→ 本仓库所有构建日志必须过滤该行。
- 更早手工实验（16 字节 header_key）报错原文:
                     "Key (000102030405060708090a0b0c0d0e0f) must be 64 hex digits!"
  → 证实 header_key 必须 32 字节（64 hex，XTS）；key_area_key_application_xx 为 16 字节（32 hex）。

## 6. 非确定性的源码依据（补充）
- rsa.c rsa_sign(): mbedtls_rsa_set_padding(MBEDTLS_RSA_PKCS_V21, MBEDTLS_MD_SHA256) → RSA-PSS，
  签名用 mbedtls_ctr_drbg_random 随机盐，因此同一输入每次签名不同。
- nca.c:667-670: if (settings->nosignncasig2 == 0) { rsa_sign(&nca_header.magic, 0x200, ...); }
  → 两次构建 Program/Meta NCA 的签名/哈希不同，NSP 整体 SHA-256 不同。

## 7. 与 nstool 的关系（详见 M3a-nstool-verify.txt）
- nstool 校验 NSP 层（PFS0）不需要 keyset；
- nstool 读 NCA 内容/校验必须传入与构建一致的 header_key，否则:
  "[nstool::SettingsInitializer ERROR] Input file type was undetermined."（exit 1）
- 由此可见「出包成功」与「可被读回/可被系统解密」是两个不同门槛：
  前者只要任意格式合法的 keyset，后者需要目标机可用的真实 keys。
