## 1. NSP 层（nstool -y -k <real keys> m0 构建）
$ nstool -y -k <keyset> m0-hello-0100000000001000.nsp
[WARNING] Failed to load "title.keys" keyfile.
[PartitionFs]
  Type:        PFS0
  FileNum:     3
NSP_VERIFY_EXIT=0

判读: exit 0 只说明 NSP 是合法 PFS0 且含 3 个文件；nstool 不在此层展开/校验 NCA。
      同一命令换成不匹配 keyset 也 exit 0（见 §4），说明 NSP 层校验与 keyset 无关。

判读: nacptool 默认生成 62 MiB 存盘 + 1 MiB journal，并非 0；若 M3 需要「无存档 forwarder」
      或自定义存档隔离策略，必须在 NACP 层显式处理（nacptool 无该选项，需后改二进制或换工具）。

## 5. 跨 keyset 实验（证明 header_key 是 NCA 头解密的必要条件）
(a) real keyset 读 synthetic 构建的 Program NCA
[WARNING] Failed to load "title.keys" keyfile.
[nstool::SettingsInitializer ERROR] Input file type was undetermined.
REAL_KEYS_ON_SYNTH_NCA_EXIT=1

(b) synthetic keyset 读 real 构建的 Program NCA
[WARNING] Failed to load "title.keys" keyfile.
[nstool::SettingsInitializer ERROR] Input file type was undetermined.
SYNTH_KEYS_ON_REAL_NCA_EXIT=1

(c) 对照：NSP 层（只列 PFS0）用不匹配 keyset 仍成功
[WARNING] Failed to load "title.keys" keyfile.
[PartitionFs]
  Type:        PFS0
  FileNum:     3
REAL_ON_SYNTH_EXIT=0 / SYNTH_ON_REAL_EXIT=0

判读: ①「nstool -y 校验 NSP」本身不等于校验内容，必须逐个 NCA 再验；
      ② NCA 层解密/识别必须使用与构建完全一致的 header_key（synthetic 与 real 不通用）；
      ③ 真实 keyset 的价值体现在能否读回 NCA 内容（以及真机安装时能否被系统解密）。
